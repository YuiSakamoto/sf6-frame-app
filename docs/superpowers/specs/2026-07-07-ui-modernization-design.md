# SF6 Frame App UI モダナイゼーション 設計書

日付: 2026-07-07
ステータス: 承認済み

## 背景と目的

sf6-frame.app(Web)と iOS/Android アプリの UI を 2026 年水準に刷新する。対象は
ビジュアル刷新・UXフロー改善・技術基盤の現代化・アクセシビリティの4領域。
Web とネイティブは同等の優先度で扱う。

ユーザーが把握している現状の課題:

- 検索が弱い(コマンド表記や通称でヒットしない)
- フレーム表の見やすさに改善余地がある
- 確反検索の3ステップウィザードが試合の合間に引くには遅い

## 決定事項サマリ

| 論点 | 決定 |
| --- | --- |
| デザイン方向 | C. Pro Data Tool(ニュートラルダーク・情報密度・実用特化) |
| スタイリング基盤 | 自前デザイントークン + useTheme(NativeWind は削除) |
| テーマ | システム追従 + 手動切替(light / dark / system) |
| 確反フロー | 1画面完結(vs バー + 検索 + インライン結果展開) |
| フレーム表(モバイル) | 技名列固定 + 横スクロールで全列表示 |
| フレーム表(デスクトップ) | 全列テーブル + ソート可能ヘッダー |

## 1. デザインシステム

### トークン(`src/theme/tokens.ts` 新設)

- ニュートラルダーク / ライトの2パレットと、それを参照するセマンティックトークン:
  `bg` / `surface` / `surfaceRaised` / `border` / `textPrimary` / `textSecondary` /
  `textMuted` / `accent`(ブルー系)/ `framePositive`(緑)/ `frameNegative`(赤)/
  `frameNeutral`
- スペーシングは 4px 基準のスケール、角丸・タイポグラフィスケールも定義
- フレーム数値の表示は全箇所 `fontVariant: ["tabular-nums"]`
- テキスト/背景のコントラストは WCAG AA(4.5:1)を満たす値にする
- `src/theme/characterColors.ts`(キャラ別グラデーション)は現行維持
- 旧 `src/theme/colors.ts` はトークンへ移行後に削除

### テーマシステム

- `ThemeProvider`(React Context)+ `useTheme()` フックを新設
- `useSettingsStore` に `themeMode: 'system' | 'light' | 'dark'` を追加(persist 対象)
- `system` 時は `useColorScheme()` に追従。StatusBar / SystemUI の色も連動
- 設定画面にテーマ切替 UI を追加

### 依存整理

- `nativewind` / `tailwindcss` を devDependencies から削除(未配線・未使用のため)
- `src/global.css` / `nativewind-env.d.ts` を削除
- 既存の StyleSheet 実装は `useTheme()` からトークンを受け取る形に書き換える

## 2. 確反検索の1画面化

`src/app/(tabs)/punish.tsx` を全面改修する。

- 画面上部に「自キャラ vs 相手キャラ」バー。各キャラをタップすると
  `CharacterSelectModal` が開き、⇄ ボタンで自分/相手を入れ替え
- その下に技の検索ボックスとソート(発生順 / ダメージ順の FilterChip)
- 相手の技リストの各行に「ガード時フレーム」と「確反あり N 件 / 確反なし」バッジを
  最初から表示する
- 行タップでその場に反撃技リスト(技名・発生・猶予フレーム・ダメージ)を展開
- 確反計算は既存の `punishService` / `punishCalc` を流用
- 現行の `Stepper` と3画面遷移は廃止。自キャラ未設定時は従来どおり
  `CharacterGrid` で選択を促す

## 3. フレーム表の刷新

`src/app/character/[slug].tsx` と `src/components/frame-data/` を改修する。

### モバイル(< 768px)

- 技名列を固定し、数値列(発生 / 持続 / 硬直 / ガード / ヒット / キャンセル /
  ダメージ / ドライブ・SA ゲージ増減)を横スワイプで全列閲覧できるテーブル
- 実装: 行高を固定し、「固定の技名列」+「横スクロール領域の数値グリッド」の
  2ペイン構造。縦スクロールは共通の親が担い、左右の行ズレを防ぐ
- Web(モバイル幅)では CSS `position: sticky` による技名列固定が使えるため、
  react-native-web ではそちらを優先する

### デスクトップ Web(≥ 768px)

- 全列を一画面に表示し、ヘッダークリックでソート(発生 / ガード時 / ヒット時 /
  ダメージ。再クリックで昇順・降順トグル)

### 詳細シート

- 備考・コンボ補正など長文情報は行タップで開く軽量な詳細シート
  (モバイル: ボトムシート、デスクトップ: モーダル)に表示し、テーブルには乗せない

## 4. 検索強化

`src/utils/search.ts` を拡張する(既存テストは維持し、新規ケースを追加)。

- コマンド表記検索: `236P` `623HP` `5MP` などテンキー表記でヒット
- エイリアス辞書: 「昇竜」「DP」「波動」「足払い」「中足」などの通称を
  正式技名にマッピング
- ひらがな / カタカナ / ローマ字の正規化(NFKC + かな変換)
- フィルタ追加: キャラ・カテゴリに加えて「発生 N フレーム以下」
  「ガード時 -N 以下(確反探し用)」
- 検索ロジックは純関数として実装し、vitest でユニットテストを書く

## 5. アクセシビリティと磨き込み

- 全インタラクティブ要素(Pressable / タブ / チップ / 行)に
  `accessibilityRole` と `accessibilityLabel` を付与
- タッチターゲットは 44pt 以上を確保
- Reanimated のマイクロインタラクションは維持しつつ、`useReducedMotion` で
  アニメーション減弱設定に追従
- ネイティブのみ `expo-haptics` を追加し、タブ切替・キャラ選択時に軽い触覚
  フィードバック(Web は no-op)
- ローディングはスケルトン表示に統一。検索0件・データ未取得・オフライン時の
  エンプティステートを整備(既存の Result 型によるエラーハンドリングは維持)

## 6. スコープ外(YAGNI)

- FlashList 導入 — 全データ ~2,200 行程度で FlatList の仮想化で十分
- PWA 化・オフラインキャッシュ強化
- Expo SDK / React Native のバージョン更新(現行 SDK 55 のまま)
- 全面リデザイン級のブランド変更(方向性 C の範囲に留める)

## テスト・検証

- ユニットテスト(vitest): 検索パーサ・エイリアス正規化・確反計算・
  テーマトークンのコントラスト検証
- `pnpm typecheck` / `pnpm lint` / `pnpm test` を全通過させる
- Web: Playwright で主要3画面(技表 / 確反 / 検索)のスモーク確認
- ネイティブ: iOS シミュレーターで目視確認(テーマ切替・横スクロール表・確反展開)

## 実装順序(概要)

1. デザイントークン + ThemeProvider + 設定画面のテーマ切替(基盤)
2. 共通 UI コンポーネントのトークン移行(Badge / FilterChip / SearchBar 等)
3. フレーム表の刷新(モバイル横スクロール + デスクトップ全列)
4. 確反1画面化
5. 検索強化
6. アクセシビリティ・ハプティクス・エンプティステートの仕上げ
7. NativeWind 削除などの依存整理

詳細なステップは writing-plans で実装計画として別途作成する。
